# ARCHITECTURE.md — RCON Warfare

Назначение: объяснить, **как проект устроен и почему именно так**, чтобы новую
функцию (или v16) можно было вписать, не сломав инварианты. Если документ
противоречит коду — верь коду и поправь документ.

Связанные документы: [`README.md`](README.md) — обзор и запуск,
[`HANDOFF.md`](HANDOFF.md) — состояние и план, [`BUGS.md`](BUGS.md) — реестр
дефектов, [`SKILL.md`](SKILL.md) — знания про Minecraft/RCON,
`skills/tactical-ui-dearpygui.md` — приёмы Dear PyGui.

---

## 1. Что это

Диспетчерская боевой техники для сервера Minecraft: оператор управляет
самолётами, вертолётами, БПЛА, танками и транспортом **с карты**, а не из
игры. Связь с сервером — единственный канал: протокол **Source RCON**.
Техника материализуется в мире **блоками** (клиент-серверная модель: сервер
рисует юнит из блоков, клиент только шлёт команды).

Целевая платформа: Minecraft 1.20.1 vanilla (Paper/Spigot), совместимость с
1.21.2+ через диалекты NBT.

## 2. Слои

```
        ┌──────────────────────────── UI (главный поток) ───────────────────────────┐
        │  build.py (виджеты)   project.py (STATE → виджеты)   mapfacade.py (карта) │
        │  context.py (ПКМ)     painter.py (примитивы → emit)  dialog.py (Tkinter)  │
        └───────────────▲──────────────────────────────────────────┬───────────────┘
                        │ MSG_Q (сообщения)                        │ OUT_Q (команды)
        ┌───────────────┴──────────────────────────────────────────▼───────────────┐
        │                          facade.py :: CoreFacade                          │
        │     поток снимков (15 Гц)                 поток управления (колбэки UI)   │
        └───────────────▲──────────────────────────────────────────┬───────────────┘
                        │ EventBus (единственный канал ядро→UI)     │ вызовы ядра
        ┌───────────────┴──────────────────────────────────────────▼───────────────┐
        │                            ЯДРО (rwf/*.py, без UI)                        │
        │  app.py (композиционный корень)   engine.py (тик-цикл)   world.py (мир)   │
        │  units.py (физика)  routes.py (маршруты)  ai.py (боты)  weapons.py (огонь)│
        │  model.py (блоки)   missiles.py  combat.py  manpads.py   bases.py         │
        │  scanner.py  tracker.py  maprender.py  gamefx.py  sound.py  progress.py   │
        └───────────────▲──────────────────────────────────────────┬───────────────┘
                        │                                          │ CommandQueue
        ┌───────────────┴──────────────────────────────────────────▼───────────────┐
        │      rcon.py: RCONPool (эксклюзивная аренда) + CommandQueue (приоритеты)  │
        └──────────────────────────────┬───────────────────────────────────────────┘
                                       │ TCP
                        ┌──────────────▼───────────────┐
                        │  Minecraft (или mock_server) │
                        └──────────────────────────────┘
```

**Жёсткое правило:** всё, что в `rwf/*.py` (кроме `rwf/ui/`), не знает про
Dear PyGui. Проверка:

```bash
grep -r "import dearpygui" rwf/*.py     # должно быть пусто
grep -rn "rcon\|RCONPool\|CommandQueue" rwf/ui/   # только facade.py
```

## 3. Инварианты (нарушение = баг, а не «стиль»)

| Инвариант | Где живёт | Что означает |
|---|---|---|
| Ядро без UI-зависимостей | `rwf/*.py` кроме `ui/` | связь только через `EventBus` |
| STATE трогает только главный поток | `ui/app.py::drain_messages` | рабочие потоки кладут в `MSG_Q`, не мутируют STATE |
| Ядро вызывается только через `OUT_Q` | `ui/facade.py::send` | колбэк UI никогда не блокируется на сети |
| `rcon.run()` не вызывается из UI и из тика | `rcon.py` | иначе кадр/тик ждёт сеть |
| Все команды — через `CommandQueue.submit` | `rcon.py` | иначе нет приоритетов и слияния |
| `BlockModel.sync` идемпотентна | `model.py` | повторный вызов без смены позы = 0 команд |
| `CommandQueue` мержит по ключу-позиции | `rcon.py` | иначе от залпа останется один блок |
| Модель убирает только свои блоки | `model.py::clear` | чужой ландшафт не трогается (UNIT-12) |
| Координаты блока — `round()`, не `int()` | `model.py` | `int(-3.7) == -3`, модель «прыгает» (UNIT-13) |
| Производные в физике × dt | `units.py` | иначе скорость зависит от частоты тика |
| Углы/векторы — только из `geometry.py` | `geometry.py` | один источник правды |
| Домен → слово — только `unitstate.describe()` | `unitstate.py` | один перевод «техника → состояние» |
| Регрессионные метки не удалять | по всему коду | `UNIT-11`, `ROUTE-04`, `AI-01`… — исполняемая документация |

## 4. Потоки и жизненный цикл

| Поток | Что делает | Частота |
|---|---|---|
| главный (DPG) | `drain → project → map → render` | кадр |
| `ui-snapshots` | снимки мира/баз/рельефа в `MSG_Q` | 15 Гц (медленные данные — 2 Гц) |
| `ui-control` | команды из `OUT_Q` → вызовы ядра | по событию |
| `engine` | `tick_once`: физика, маршруты, ИИ, модель | `sim.tick` (0.25 с) |
| `scanner` | пакетное зондирование рельефа | по запросу |
| `tracker` | опрос игроков | по настройке |
| `gun_poller` / `manpads` | триггеры из игры (`rwf_lock`, `rwf_fire`) | опрос |

**Порядок остановки — обратный порядку запуска** (`Application.disconnect`):
движок → поллеры → трекер/сканер → очередь → пул. Нарушение = гонка на
разборке контекста.

## 5. Модель производительности кадра

Кадр состоит из четырёх фаз; профиль включается `RWF_PROFILE=1` и печатает
сводку раз в 30 кадров:

```
[FPS-02] 30 кадров за 0.68 с → 43.9 fps | мс/кадр: drain 0.01  project 9.8  map 4.7  render 7.7
```

Правила, которые уже оплачены багами:

1. **Проекция не ходит на диск.** `project._project_presets` вызывается
   каждый кадр; каталог пресетов кэшируется в `PresetLibrary` (FPS-03:
   без кэша 9 чтений JSON на кадр дали 2.4 fps).
2. **Проверка «изменилось ли» стоит ДО дорогой работы.** Кэш `sig` в
   `project.py` бесполезен, если подпись считается после чтения данных.
3. **Фон карты кэшируется** по ключу камеры и содержимого слоёв
   (`mapfacade._bg_key`, FPS-01). Юниты/игроки/HUD — всегда свежие.
4. **Растр рельефа** кэшируется по `descriptor()` сетки, а не по камере;
   конвертация в float — в рабочем потоке (I5), не в кадре.
5. `dpg.delete_item(PEN, children_only=True)` + перерисовка примитивов —
   единственный путь рендера карты (`painter.paint`).

## 6. Грабли Dear PyGui 2.3.1 (собрано на своих ошибках)

| Грабли | Симптом | Как правильно |
|---|---|---|
| `get_item_rect_min/max` у **окон** | `KeyError('rect_min')` **всегда** (у drawlist ключ есть) | `get_item_pos` + `get_item_rect_size` (DPG-11) |
| ширина окна < 100 px | **тихо** остаётся 100 px: `configure_item(width=34)` не действует (высота — действует) | проектировать узкие панели ≥ 100 px и сверять раскладку замером (DPG-12) |
| `add_tooltip` на контейнере | abort в нативном слое, `try/except` не берёт | `build._tip` + `_TIP_UNSAFE` |
| `dpg.tooltip()` как контекст-менеджер | «No container to pop» | `dpg.add_tooltip(parent=…)` функцией |
| `add_theme_color(parent=theme)` | молча не применяется | только `add_theme_component` |
| Второй DPG-контекст в процессе | ABI-краш | один `run()` за процесс, проверки внутри `on_frame` |
| `add_text` без `width` | колонки разъезжаются | обёртка `tcol()` |
| `add_selectable` | значение только `bool` | текст через `configure_item(label=…)` |
| overlay прогресс-бара | непредсказуемый контраст | значение печатать текстом рядом |
| `add_drag_payload` | нет параметра `data` | данные через `drag_data` |

## 8. Тесты как контракт

```bash
python -m pytest tests/ -q          # 596 тестов, GL не нужен
python main.py --selftest           # то же через штатный вход
RWF_UPDATE_GOLDEN=1 python -m pytest tests/test_golden.py   # переснять эталоны
```

* **~596 тестов**, ядро проверяется без GL. Метки дефектов в докстрингах
  (`"""Регресс UNIT-11: …"""`) — часть контракта.
* `test_ui_dpg.py::TestHeadlessRender` — **единственный** сквозной прогон
  настоящего `run()`; исполняется там, где есть GL-окно (на Linux — под
  `xvfb-run`, отключается `RWF_NO_UI=1`).
* `test_golden.py` — канонический лог примитивов силуэта по хешу: ловит
  случайную правку формы без зависимости от рендерера.
* Стиль: seed для детерминизма, `FakeQueue`/`FakePool` вместо моков
  библиотек, границы (`delta=`) вместо точного равенства в физике.

## 9. Известный долг (перед v16)

1. **`CoreFacade.tac_apply` читает живой STATE из потока управления.**
   Формально нарушает «STATE трогает только главный поток». Готовая
   правильная граница — `CoreFacade.assign_route_points` (чистые словари).
   Рядом — мёртвый дубль `CoreFacade.tac_select`.
2. **`EventBus` — подписка через `subscribe("*")`**: нет типизации тем,
   новая тема легко забывается в `_BUS_LOG`.
3. **Нет `pyproject.toml`/`pytest.ini`**: `rootdir` без конфига, зависимости
   CI ставятся вручную.
4. **`numpy`/`pillow` необязательны**, но ветки с ними и без них
   различаются по скорости на порядок — стоит зафиксировать в требованиях.
5. **Профиль кадра не измеряется в тестах**: перф-порогов (`test_perf.py`) нет.

## 10. Направление v16

Заявлено заказчиком: **3D-карта**, **воксельный мир**, обновлённый UI и
функционал. Что из текущей архитектуры этому помогает и что мешает:

* **Помогает:** `maprender` уже отдаёт примитивы через `painter` (замена
  эмиттера на 3D-проекцию не трогает ядро); `TerrainRaster` уже есть —
  воксельный мир это его расширение по Y, а не новый источник данных;
  `geometry.py` — готовый слой математики для матриц камеры.
* **Мешает:** карта завязана на экранные координаты (`MapTransform.to_screen`)
  в хит-тестах и слоях; STATE держит плоские 2D-структуры; `painter`
  знает только 2D-примитивы. Разделять придётся на границе
  «мир → камера → примитивы», оставив `painter` 2D-растеризатором кадра.
