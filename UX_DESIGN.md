# UX_DESIGN.md — что делает оператор и как это должно работать

Разбор «со стороны игрока и оператора» + спецификация трёх переделок:
**окно настроек**, **пресеты**, **логи на F1**. Это задание на реализацию, а не
отчёт: пункты со статусом ⬜ ещё не сделаны.

---

## 1. Кто пользователь и что он делает

Пользователей двое, и раньше они в документах были смешаны.

### 1.1. Игрок в Minecraft (его интерфейс — чат и actionbar)

Что он делает по факту:

| Момент | Что он видит сейчас | Что было бы лучше |
|---|---|---|
| Техника пролетает рядом | блоки-модель, `[RWF] …` в чате | ничего не менять: модель и есть главный сигнал |
| По нему применили оружие | `tellraw` строкой в чате | **actionbar** вместо чата — бой не должен тонуть в общем чате |
| Его захватил ПЗРК | сообщение в чате | **отдельный тип сигнала** (title/subtitle + звук) и повтор раз в секунду, пока захват держится |
| Он сам ПЗРК-оператор | подсказка про триггеры `rwf_lock`/`rwf_missile` | показать состояние «готов к пуску / перезарядка» прямо на экране |
| Он цель бомбового удара | ничего | предупреждение по рубежу сброса (`ROUTE-04`) — это честно по отношению к игроку |
| Он сбит | кратер/остов на месте падения | строка «кто сбил» в чате — сейчас в кил-фиде нет адресата |

Правило для игрока: **чат — для редкого и важного, actionbar — для состояния**.
Сейчас `mc.tellraw` — основной канал, а actionbar есть в `gamefx`, но
используется меньше, чем следовало бы.

### 1.2. Оператор (главный пользователь этого интерфейса)

Его первая минута сейчас: `python main.py` → **отдельное окно Tkinter** →
заполнить хост/порт/пароль → «ОК» → открывается диспетчерская → и только тут
он видит карту. Два окна, два набора настроек, сброс контекста на ровном месте.

**Что должно быть вместо** (см. §2): сразу диспетчерская, где подключение —
такая же настройка, как всё остальное.

## 2. Первый запуск — целевой поток

```
python main.py
   └─ сразу окно диспетчерской (Tkinter вырезан, ничего не спрашивается)
        ├─ в заголовке карты: «○ не подключено»   ← честное состояние
        ├─ секции справа пусты, но карта/инструменты живы (можно смотреть демо)
        └─ F1 → логи, Ctrl+, → настройки, где первая секция «Подключение»
```

Принципы, из которых это следует:

1. **Никаких шагов перед работой.** Окно одно, и оно уже рабочее место.
2. **Состояние всегда видно.** Нет соединения — так и написано в заголовке
   карты; пустые панели не выглядят «сломанными», потому что в них есть
   подсказка, что делать (см. §3.3).
3. **Подключение — не ритуал, а настройка.** Живёт в окне настроек и
   запоминается (сейчас не запоминается вообще — `UI-20`).

## 3. Окно «Настройки» (⬜ не реализовано)

Отдельное окно (`win_settings`), **немодальное**, панель в пол-экрана поверх
всех, слева столбец пунктов, справа содержимое выбранного пункта. Открывается
`Ctrl+,` (привычно) и из меню/рейла. Закрывается `Esc` и крестиком.

```
┌── НАСТРОЙКИ ──────────────────────────────────────────────┐
│  ПОДКЛЮЧЕНИЕ      │  Хост   [127.0.0.1   ]  Порт [25575]  │
│  ВИД И КАРТА      │  Пароль [••••••••    ]  [x] Имитатор  │
│  ОБЪЕКТ И ПУЛЬТ   │  [Подключить] [Отключить]  ● не подключено
│  ЗАПУСК           │  [x] Запомнить подключение в rwf.json │
│  ЗВУК             │                                       │
│  ЖУРНАЛ           │  Подсказка: ...                       │
└───────────────────────────────────────────────────────────┘
```

### 3.1. Состав пунктов (что переносим, что оставляем)

| Пункт | Откуда берётся | Почему в настройках |
|---|---|---|
| **Подключение** | секция `conn` из правого дока | это настройка, а не рабочий инструмент (требование заказчика) |
| **Вид и карта** | `layers` + `view` + масштаб UI + инерция | всё про то, как выглядит карта |
| **Объект и пульт** | `chk_follow` и поведение пульта | настройка поведения, а не команда |
| **Запуск** | выбор базы/типа по умолчанию, путь к пресетам | редко меняется |
| **Звук** | `settings` (существующее) | уже настройка |
| **Журнал** | длина, фильтры, шрифт | см. §5 |

Правый док после этого: **только рабочее** — ЗАПУСК, ТЕХНИКА, БАЗЫ,
ПЛАНИРЩИК, ИИ, ПРОГРЕСС, ИГРОКИ. Это и есть главный выигрыш переделки.

### 3.2. Как это делать технически (без изобретений)

- Одно окно + `dpg.child_window` справа; слева — пул кнопок-пунктов (как
  `ctx_btn_*` в `context.py`) с подсветкой активного. Модальность не нужна:
  оператор должен видеть карту за окном.
- **Секции-строители уже есть**: `_section_builder("conn")` и т.п. Достаточно
  вызывать их в правую панель вместо дока — то есть переиспользовать код, а не
  переписывать виджеты. Ключевая проверка: теги (`in_host`, `chk_sound`,
  `sld_ui_scale`, `chk_mock`) не должны измениться, иначе `project.py` их не
  найдёт.
- Правый док перестаёт содержать перенесённые секции — из `SECTION_ICONS`
  убрать `conn`, `layers`, `settings`, `view`, `log`.

### 3.3. Пустые состояния (важно для «что делать»)

Каждая рабочая секция при отсутствии данных должна говорить, чего не хватает:
ТЕХНИКА — «нет техники: выберите базу в ЗАПУСКЕ и нажмите СТАРТ», БАЗЫ — «баз
нет: инструмент «дом» на рейле, клик по карте». Сейчас пустая таблица
неотличима от поломки.

## 4. Пресеты — переработка (⬜ не реализовано)

Что не так сейчас: секция «ЗАПУСК» = четыре комбобокса подряд (тип → пресет →
база → СТАРТ), а редактор — отдельное модальное окно с drag&drop, в которое
надо ещё догадаться войти (иконка «слайдеры» рядом с комбобоксом).

Целевое:

1. **Пресет — главный объект запуска, а не второй комбобокс.** Список пресетов
   с прокруткой, у каждого видно: силуэт, вариант, подвесы, высоту, бота.
   Один клик — выбран, СТАРТ — в воздухе.
2. **Тип техники не выбирается отдельно.** Он следует из пресета. Отдельный
   комбобокс «Тип» мешает: смена типа пересобирает список пресетов и сбрасывает
   выбор (`UI-19` в аудите).
3. **Редактор — из того же окна**, а не отдельной модалкой: «＋ Новый» и
   «Изменить» открывают правую панель редактора в том же окне запуска.
4. **База — вторая строка после пресета**, с пометкой свободных стоянок
   (`free_pads` уже есть в снимке) — чтобы «нет свободной стоянки» не выяснялось
   после нажатия СТАРТ.
5. **Старт по Enter** в этом окне и `Ctrl+Enter` из любого места.

## 5. Логи на F1 (⬜ не реализовано)

Сейчас журнал — секция правого дока: он всегда занимает место, конкурирует за
внимание с рабочими панелями и его нельзя быстро развернуть.

Целевое:

- Журнал — **отдельное окно**, скрытое по умолчанию, включается/выключается
  `F1` (и иконкой `terminal` на рейле с подсветкой «есть новое»).
- Из правого дока секция `log` убирается вместе с `conn`.
- Окно помнит размер/позицию, открывается там же, где закрыли.
- Внутри: время, уровень цветом, фильтры (связь/бой/скан/система) — сейчас
  ни времени, ни фильтров нет.
- Новое сообщение при закрытом окне — счётчик на иконке, а не потеря.
- `Esc` закрывает окно; `F1` — тумблер.

Реализация: `dpg.add_key_press_handler` в существующем `handler_registry`
(глобальные обработчики там уже есть — `mapfacade.create`), один `win_log` с
`child_window`, убрать `_dock_log` из списка секций.
