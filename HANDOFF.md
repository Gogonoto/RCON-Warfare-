## §1. Что это за проект

**RCON Warfare** (сокращённо **RWF**; историческое имя **Bomber**, встречается в
CHANGELOG и названиях версий) — тактический слой диспетчерской боевой техники
в Minecraft. Управляет техникой (самолёты/вертолёты/БПЛА/танки/транспорт),
маршрутами, оружием, базами; карта, диспетчерская, ПЗРК. Связь с сервером —
через RCON.

**Стек:** Python 3.10+, Dear PyGui 2.x (UI), Tkinter (стартовый диалог), stdlib
(RCON, wave, threading). Внешние зависимости: `dearpygui`, `pillow`;
`pygame` и `numpy` необязательны.

**Домен:** военная авиация/техника; реальные ТТХ Су-25, МиГ-29, Ка-52, Т-72 и т.д.; корректные термины (сваливание, согласованный вираж, перегрузка, рубеж захода).

**Версии:** `__version__ = "15.2.0"` в `rwf/__init__.py` (до v15.2.0 там было
застрявшее `13.0.0`). Версии по модулям и фичам — в `CHANGELOG.md`, дефекты —
в `BUGS.md`. Следующая заявленная версия — **v16** (3D-карта, воксельный мир,
обновлённый UI).

**Целевая платформа Minecraft:** 1.20.1 (vanilla); поддержка Paper/Spigot; NBT-диалект переключается в 1.21.2 (`ExplosionPower` → `explosion_power`).

**Ключевые архитектурные инварианты** (не нарушать):

| Инвариант | Где | Что значит |
|---|---|---|
| **Ядро не знает про Qt/DPG** | всё `rwf/*.py` (кроме `ui/`) | связь только через `EventBus` |
| **UI трогает STATE только в главном потоке** | `ui/app.py::drain_messages` | рабочие потоки кидают в `MSG_Q` |
| **Ядро вызывается из UI только через `OUT_Q`** | `ui/facade.py::send` | колбэки не блокируют на сети |
| **`BlockModel.sync` идемпотентна** | `model.py` | повторный вызов = 0 команд |
| **`CommandQueue` мержит VISUAL по ключу** | `rcon.py` | ключ = позиция блока, не uid |
| **Скорость/манёвренность не зависит от dt** | `units.py` | все производные × dt |
| **Модель убирает только свои блоки** | `model.py::clear` | чужой ландшафт не трогается |
| **Домен ↔ UI через `unitstate.describe()`** | `unitstate.py` | один перевод «техника → слово» |

## §3. Что в проекте сделано **сильно** (не ломать при рефакторинге)

1. **EventBus** — единственный канал ядро→UI, никаких Qt-зависимостей в ядре. Не «учебник», реальное решение против гонок.
2. **CommandQueue** с приоритетами (CRITICAL/NORMAL/VISUAL), слиянием по ключу, rate-limit'ом **общим для воркеров** (не на воркер!). Ключ слияния — позиция блока, не uid: иначе от залпа остался бы один блок.
3. **BlockModel** — дифф-обновление: `writes` (что изменилось) + `clears` (что убрать). Плюс `_model_key()` в целочисленных блоках: пока юнит не сдвинулся на полблока, проекция не пересчитывается.
4. **RecoveryNode** — единый контракт посадки для аэродрома/авианосца/вертолётной площадки. Одна структура, три сценария.
5. **TerrainRaster** кэшируется по `descriptor()` сетки, а не по камере. Пересчёт — только при изменении рельефа.
6. **MockMCServer** — говорит на настоящем RCON, держит синтетический мир, пишет `command_log`. Позволяет проверять, ЧТО именно ушло на сервер.
7. **SoundManager** — синтез WAV в stdlib, fallback pygame → CLI → null. Headless работает.
8. **Тесты** — 20 файлов, покрывают сквозные сценарии, конкурентность (8 потоков на 3 соединения), регрессионные метки (`UNIT-11`, `ROUTE-04` и т.д.), детерминизм через seed.

**Не переписывать архитектуру.** Проект уже прошёл эволюцию и «закалён» на багах.

## §4. Что НЕЛЬЗЯ делать (антипаттерны, уже один раз оплаченные)

### 4.1 Работа с DPG

❌ **Не вешать `add_tooltip` на контейнеры.** `mvTable`, `mvTableRow`, `mvWindowAppItem`, `mvChildWindow`, `mvGroup`, `mvMenuBar`, `mvTooltip` — **abort в нативном слое**, try/except не берёт. Список в `rwf/ui/build.py::_TIP_UNSAFE`.

❌ **Не вызывать `dpg.tooltip()` внутри активного контейнера.** Это не контекст-менеджер; роняет стек контейнеров («No container to pop»). Правильно: `tip = dpg.add_tooltip(parent=X, delay=0.3)`, затем `dpg.add_text(..., parent=tip)`.

❌ **Не класть цвета/стили в саму тему.** `dpg.add_theme_color(parent=theme)` **молча не применяется**. Только `dpg.add_theme_component(parent=theme)`.

❌ **Не создавать второй DPG-контекст в одном процессе.** ABI-ограничение. В тестах — один `run()` за процесс, все проверки внутри `on_frame`.

❌ **Не рисовать карту через `dpg.draw_*` вне `mapfacade.py`.** Весь рендер идёт через `painter.paint(emit, prims)`, где `emit` — либо `DpgEmit`, либо тестовый регистратор.

### 4.2 Работа с RCON

❌ **Не полагаться на один `recv`.** Minecraft режет ответы >4 КБ на пакеты. Правильно: послать команду, потом пустой пакет-маркер, читать до маркера.

❌ **Не делать round-robin на пуле соединений.** Два потока на одном сокете смешают пакеты. Только эксклюзивная аренда через `RCONPool.lease()`.

❌ **Не отправлять одиночные команды в цикле.** Перерисовка модели — 15-20 команд; ждать ответ на каждую = RTT × 20. Только `run_many()` (pipelining).

❌ **Не блокировать тик на сети.** Все команды — через `CommandQueue.submit()` с приоритетом.

### 4.3 Работа с моделью

❌ **Не вызывать `clear_model()` по новой позиции.** Старая останется — след из блоков через всю карту. Это **UNIT-11**, регрессионный тест `test_flight_leaves_no_trail`.

❌ **Не делать `fill ... air replace` вокруг юнита.** Стирает ландшафт и постройки. Модель убирает **только свои блоки** по точному списку. Это **UNIT-12**, `test_despawn_does_not_touch_terrain`.

❌ **Не использовать `int()` для координат блока.** `int(-3.7) == -3` — модель «прыгает» на блок при отрицательных координатах. Только `round()`. Это **UNIT-13**, `test_negative_coordinates_not_shifted`.

❌ **Не синхронизировать модель каждый тик.** `_model_key()` в целых блоках + ограничение `model_update_hz`. Иначе — 40 юнитов × 20 блоков × 20 Гц = лавина команд.

### 4.4 Работа с маршрутами

❌ **Не считать точку достигнутой по `dist <= 3`.** Самолёт на 60 м/с за тик 0.5 с пролетает 30 блоков — не попадёт в окно никогда. Два режима: `fly` (пересечение перпендикулярной плоскости точки) и `precise` (радиус + высота). Это **ROUTE-01/02**.

❌ **Не сбрасывать `current_idx` при перепланировании.** Иначе бот вечно летит к первой точке. Только `Route.replace_waypoints()` с сохранением прогресса. Это **AI-01**, `test_replan_preserves_progress`.

❌ **Не вызывать `replan()` каждый тик.** Гибрид: порог смещения цели **ИЛИ** интервал **ИЛИ** завершение маршрута.

❌ **Не сбрасывать бомбы после пролёта точки.** Сброс — **ДО** точки, на дистанции `V × sqrt(2h/g)`. Это **ROUTE-04**, `test_bomb_releases_before_target`.

❌ **Не оставлять действие без таймера.** Любое действие заканчивается по `duration` или по общему предохранителю. Это **ROUTE-03**, `test_timeout_advances_instead_of_hanging`.

### 4.5 Работа с физикой

❌ **Не путать дельты и абсолютные цели управления.** `set_target(pitch=-10)` — «держать −10°», а не «прибавить −10°». Это **UNIT-01**, `test_pitch_target_is_held_not_accumulated`.

❌ **Не гасить крен самопроизвольно.** `roll *= 0.75` каждый тик — ошибка. Крен держится, пока не задана новая цель. Это **UNIT-02**, `test_roll_does_not_decay`.

❌ **Не забывать `× dt` для производных.** Иначе результат зависит от частоты тика. Все производные в `units.py` — только с `× dt`. Это **UNIT-03**, `test_dt_independent_turn_rate`.

❌ **Не возвращать `min_speed` при нулевой тяге у самолёта.** Самолёт с убранным газом **разгонялся**. Целевая скорость на малом газе — `idle_speed = stall_speed × 0.6`, ниже сваливания. Это **UNIT-09**.

❌ **Не считать у самолёта вертикальную скорость от тангажа.** Только от `forward_vector(yaw, pitch).y × speed`. Иначе `vs` не имеет знака.

### 4.6 Работа с оружием

❌ **Не хардкодить боезапас и темп.** `count` и `rate` лежат в `WEAPONS`; хардкод 0.8 с для УР — это **WPN-08**, `test_cooldown_blocks_immediate_second_shot`.

❌ **Не спавнить `fireball` с полем `direction`.** Такого поля нет, параметр молча игнорируется. Только `Motion` + `power:[0,0,0]`. Это **WPN-02/WPN-03**.

❌ **Не спавнить залп в одной точке.** Все бомбы/снаряды в точке носителя → один взрыв вместо серии. Веер через `bomb_interval` и `_spread`. Это **WPN-09**.

❌ **Не пускать УР без цели.** Боезапас тратится впустую, ракета летит в никуда. Только при `target != None`.

❌ **Не выдавать «частичный» боезапас.** Топливо/ремонт — пропорционально при дефиците. Патроны — либо полностью, либо нет.

### 4.7 Работа с состоянием

❌ **Не отдавать наружу живые словари.** `snapshot()` возвращает **копии**; иначе UI-поток перебирает `waypoints`, пока движок их меняет — `RuntimeError: list changed size during iteration`. Это **WORLD-02**, `test_snapshot_survives_concurrent_route_mutation`.

❌ **Не делать `read-modify-write` счётчиков из нескольких потоков.** `world.scan_progress[0] += 1` из 6 потоков теряет инкременты. Только под локом. Это регресс `test_scan_progress_is_atomic`.

❌ **Не оставлять `set_route(uid, None)` без защиты.** Следом не должно быть `route.owner_kind = ...` — упадёт на `None`.

❌ **Не забывать удалять вышедших игроков.** `world.sync_players()` — обязателен. Иначе «призраки» на карте навсегда.

### 4.8 Работа с базами и службой

❌ **Не делать ручное ТО основной кнопкой.** Заправка/снаряжение/ремонт — **автоматически** по касанию базы. Оператор управляет **режимом службы** (`park`/`combat`), не услугами. Это UX-15.

❌ **Не позволять очкам снабжения кончаться в ноль.** `SUPPLY_FLOOR = 5.0` — неснижаемый остаток. Иначе база «схлопывается» навсегда.

❌ **Не давать авианосцу своей генерации снабжения.** `supply_regen = 0`; только доставка транспортником. Это фича, не баг.

### 4.9 Работа с версиями Minecraft

❌ **Не хардкодить NBT-имена.** `ExplosionPower` (legacy) vs `explosion_power` (modern, 1.21.2+). Только через `NbtDialect`.

❌ **Не определять версию по строке.** Только зонды без побочных эффектов: `execute if entity @e[type=minecraft:marker,...]` (маркер с 1.17), `block_display` (с 1.19.4), `/ride` (с 1.20.5), `/damage` (с 1.19.4).

### 4.10 Работа с кодом вообще

❌ **Не смешивать feature-изменения и рефакторинг.** Отдельные коммиты. Тесты должны проходить на обоих.

❌ **Не удалять регрессионные комментарии вида «регресс UNIT-11».** Они — исполняемая документация. Если поведение уточняется — обновлять текст, а не удалять.

❌ **Не создавать второй источник правды.** Формулы углов — только в `geometry.py` (см. §5). Каталог оружия — только в `weapons.WEAPONS`. Пресеты — только в `presets.py`.

## §8. Правила работы с этим проектом

1. **Домен знай.** Тангаж ≠ рысканье ≠ крен. Сваливание — реальная вещь. Согласованный вираж: `n = 1/cos(φ)`. Если не уверен — спроси или прочитай докстринг модуля.

2. **Комментарии — не украшение.** В этом проекте докстринг длиннее кода — норма. Он документирует ИНВАРИАНТ, а не факт «метод возвращает True». Сохраняй при рефакторинге.

3. **Метки дефектов.** Формат `XYZ-NN`: `AI`, `UI`, `UNIT`, `WPN`, `ROUTE`, `MAP`, `GAME`, `SET`, `GROUND`, `WORLD`, `WRECK`, `BASE-HP`, `ECO`, `TRANSPORT`, `REAL`, `LAUNCH`, `TAC`, `HUD`, `UX`, `SND`, `DPG`, `FPS`. При исправлении — обнови и код, и тест, и строку в [`BUGS.md`](BUGS.md) (реестр дефектов; отдельного `DEFECTS.md` в проекте нет).

4. **Ядро не знает про Qt/DPG.** Единственный канал — `EventBus`. Проверка: `grep -r "import dearpygui" rwf/*.py` должно вернуть пусто.

5. **UI не делает сеть.** Единственный путь — `CoreFacade.send(...)`. Проверка: `grep -r "rcon\|RCONPool\|CommandQueue" rwf/ui/` — только в `facade.py`.

6. **Все команды на сервер — через `CommandQueue.submit`.** Проверка: `grep -rn "\.run(" rwf/*.py` — должно быть только в `scanner.py`, `tracker.py`, `combat.py::PlayerGunPoller`, `manpads.py::ManpadsSystem` (там опрос триггеров, не команд).

7. **Не ломай инварианты из §2.** Если рефакторинг требует нарушить — обсуди, это повод пересмотреть архитектуру, а не «срезать угол».

8. **`BlockModel.sync` идемпотентна.** Не вызывай, если не собираешься менять позу — дорого по проекции, бессмысленно по результату.

9. **Порядок остановки — обратный порядку запуска.** `Application.disconnect`: сначала движок, потом поллеры, потом трекер/сканер, потом очередь, потом пул. Нарушишь — гонка на разборке контекста.

10. **Не изобретай второй способ.** Если что-то уже есть (углы в `geometry.py`, каталог в `weapons.py`, состояния в `unitstate.py`, парсеры в `mc.py`) — используй, не пиши параллельно.
